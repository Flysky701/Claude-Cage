# Windows 沙箱当前状态

更新：2026-11-18。目标：隔离环境并承接 Cage 原有本机功能；手机远程、云端和多设备连接后续处理。逐项范围与代码入口见 [LOCAL-FEATURES.md](LOCAL-FEATURES.md)。

本轮已按用户要求暂停，进展保存到 `codex/windows-appcontainer`。暂停时的应用兼容、持久环境与剩余工作以 [AppContainer 当前状态](../windows-appcontainer/STATUS.md) 为准，未切换产品默认后端。

## 当前判断

Sandboxie Lite 已有可运行的单应用基础，本轮补了离线模式、宿主凭据保护、显式项目共享与浏览器代理。**完整隔离与 Cage 本机功能承接尚未完成**，不能作为现有虚拟机后端的等价替代。

用户已同意评估 Windows 自带 AppContainer / LPAC，减少对 Sandboxie 高级证书功能的依赖。评估不是更换决定：现有 Sandboxie 实现与数据保留，不安装证书、不卸载引擎。[候选实测](../windows-appcontainer/STATUS.md)已通过普通 AC 本地边界、真实交互终端、Cage 终端协议连接、单端口准入及模拟代理既有连接切断；真实图形应用仍有兼容缺口，完整工作台未接入。两条路线的验证结果不能混用。

## 本轮已实现

- `--offline`：不读取连接凭据、不启动 Mihomo；保留本机工具，业务网络关闭。
- 新 v2 盒身份：保留旧数据，不导入旧盒中可能已经复制的宿主配置。
- Windows 运行环境变量白名单；固定宿主凭据、浏览器资料与临时目录的盒内独立视图；Cage 控制配置和其他盒物理目录封闭。
- 用户注册表盒内持久化，默认关闭剪贴板与 SMB，移除管理员权限。
- `sharedFolders` 显式只读或读写共享；运行依赖目录只读；盒内新生成的程序可使用已授权可写目录。
- Edge 独立资料入口与仅当前盒进程可用的 HTTPS CONNECT 代理。普通 HTTP、局域网和本机开发服务暂不支持。

## 本轮验证

环境：Windows build 26300 x64，Sandboxie Plus 1.18.8 / core 5.73.8，Python 3.13.15。没有修改全局 WFP、系统代理、时区或用户剪贴板，没有使用真实账号和付费 API。

| 项目 | 结果 | 范围 |
| --- | --- | --- |
| 策略输入与环境变量测试 | 7 项通过 | 路径规则注入、重叠授权、凭据保护、离线无连接配置 |
| 真实离线隔离夹具 | 首次启动及重启通过 | 合成凭据与宿主变量不可读；普通文件和注册表变更仅留盒内；授权读写共享生效；只读共享拒绝写入；盒内生成 EXE 的输出可发布；其他盒模拟物理资料不可读 |
| 离线网络夹具 | 通过 | 本机正运行回环监听未收到盒内连接；同步 DNS 返回失败。不是任意底层网络接口的完整证明 |

## 仍需完成

1. **完整宿主读取隔离**：免费经典规则下，固定敏感资料之外的宿主文件仍可能可读；未声明完成。先评估 AppContainer / LPAC，不通过写入高级配置假装免费解锁。
2. **环境级多应用管理**：当前按 EXE 分盒，主进程退出结束整盒；需支持同环境终端、浏览器、编辑器和 Desktop 并行及工作台重连。
3. **工作台接入**：复用 Cage 的项目、终端、浏览器、账号和维护接口。现有 Hyper-V 身份、安全启动、vTPM、无网卡检查不能复用为沙箱通过证明。
4. **真实工具兼容**：Claude Code / Desktop、编辑器、登录回调、多账户、附件、下载、剪贴板、工具安装和升级逐项验证。时区当前仍限部分 x64 Win32 路径的东京配置。
5. **完整网络范围**：任意目的地透明 TCP、异步 DNS、内核阻断、浏览器首次脚本时区和受控本地开发预览仍有缺口。
