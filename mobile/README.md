# 在手机上使用 Cage

手机 Cage 是远程客户端。点首页中央的「连接电脑」，用二维码或配对码连接主机，即可查看项目、接续 Claude Code 会话和处理工具审批。配对后还可在手机上操作主机里的浏览器和 Claude Desktop。代理、时区和语言在远程主机的 Cage 中设置。右上角的设置提供主题和电脑连接选项。

Android arm64 APK 可从[官网下载入口](https://claude-cage.com/#download)获取，支持 Android 8.0+。iOS 17+ 设备版由用户通过 Xcode 在本地构建并签名安装。

### Android 实验版：在本机空间打开 Claude

#### 独立 microG 空间

在 Android 16 arm64 真机上，已从新空间导入上游 microG Services 0.3.18.252432 和 Google 签名的 Play 商店 45.7.17。它有自己的应用数据和代理助手，可以与原有套件空间并存。原版商店已打开到「登录」，microG 自带的「添加 Google 账号」也能打开。

三次点 microG 的登录确认后，界面均停在「正在建立到 Google 服务器的连接」，没有出现邮箱输入框。第二次在助手验证出口后冷启动空间，第三次开启 microG 的设备注册，结果相同。复测中登录网页报告加载结束，但界面仍显示等待页。来宾进程启动时，内核拒绝了直接创建 IPv4 和 IPv6 的 TCP、UDP 套接字。这个版本尚未完成 Google 登录和商店下载，SIM、语言和时区沿用原有实现，本轮未重新测量。

11 月 14 日在同一真机复测，同一 microG 进程经现有 Java 代理向 `accounts.google.com` 发送 HTTPS HEAD 请求，收到 HTTP 302。登录用的 WebView 则返回 `getBlockNetworkLoads() == true`。它在主框架加载结束后显示的是 Chromium 内部错误文档，错误码为 `ERR_CACHE_MISS`，表单和脚本数都为 0，WebView 仍处于隐藏状态。Android 在应用缺少 `INTERNET` 权限时默认阻止 WebView 网络加载。当前空间的代理接管 Java 请求，未接入登录网页的 Chromium 网络栈。[Android WebView 网络设置](https://developer.android.com/reference/android/webkit/WebSettings#setBlockNetworkLoads(boolean)) · [Chromium 的 WebView 进程架构](https://chromium.googlesource.com/chromium/src/+/HEAD/android_webview/docs/architecture.md)

1. 安装实验包里的 `Cage-microG-Space.apk` 和 `Cage-microG-Relay.apk`。在「Cage microG 空间 → 导入 Google 套件」选择 `Cage-microG-Play.zip`，也可分别选择上游 microG Services 和原版 Play 商店的完整 APK。[microG 发布页](https://github.com/microg/GmsCore/releases/tag/v0.3.18.252432) · [上游安装说明](https://github.com/microg/GmsCore/wiki/Installation)
2. 在「配置空间代理」保存自己的 SOCKS5 出口并启动，看到「核心运行中」后返回。进入「打开 microG 设置 → Google 账号 → 添加 Google 账号」。在 microG 的确认页点「登录」。空间保留原有的来宾网络权限限制。
3. 「打开空间里的 Play 商店」启动这份独立的商店副本。「空间设置」进入该空间的沙箱管理界面。账号恢复、从商店安装 Claude 和完成对话仍待真机验证。

构建这个版本时，在轻量空间构建命令中加 `--microg`。需要使用现有的单节点测试配置时，代理助手的 `provision.py` 也支持 `--microg`。[轻量空间构建](sandbox/blackbox-light/build.py) · [代理助手配置](sandbox/local-core/README.md)

#### Google 官方套件空间

安装实验包里的 Cage 实验版、空间组件和代理助手三个 APK。实验版与正式客户端可以并存。首页点「打开 Claude」会先准备空间网络；首次使用在助手中保存 SOCKS5 出口，返回空间后按页面提示导入 Google 套件。「连接电脑」仍可进入原来的远程工作台。

1. 也可直接点「设置 → 空间设置 → 管理空间里的 Google 套件」。选择三个原版完整 APK 或包含它们的 ZIP（支持压缩包中 GoogleServicesFramework.apk、GmsCore.apk、Phonesky.apk 的目录结构）。组件只导入本机空间，可使用版本匹配的安装包更新。每次进入会重新读取各组件的安装状态。
2. 三个组件齐备后，可打开空间里的 Play 商店或 Claude 的商店详情。已在空间安装 Claude 时，从首页直接请求启动该副本。Google 登录、商店下载安装 Claude 和实际对话仍需运行验证。「已导入」只表示安装成功。
3. 「空间设置」里可配置、启动和停止代理，也能打开原来的沙箱应用列表。当前网络适配支持所列 Google 和 Claude 域名的 Java HTTPS 连接。使用自带原生网络库的应用是否能完成登录和下载，仍需逐项验证。

2026-11-13 在 Android 16 arm64 真机上，从 Cage 的文件选择器一次导入独立 ZIP。空间回读到 Google 服务框架 16、Play 服务 25.38.30 和 Play 商店 45.7.17。个人区原有套件保留。修复商店多个页面同时匹配时的启动选择后，空间内能显示 Play 商店的「Sign in」页。点击已实际送达，Google 账号服务随即拒绝此空间进程以 `ACCOUNT_MANAGER` 权限添加账号。账号输入页未出现，Claude 的商店安装、登录和对话仍未通过。该权限由系统签名保护。[Android 权限说明](https://developer.android.com/reference/android/Manifest.permission#ACCOUNT_MANAGER)

同机后续修复了零账号时的验证服务发现。可查询 Play 服务的应用能发现 1 个 Google 验证服务，未声明查询的应用和没有安装 Google 套件的另一轻量空间都返回 0。修复账号选择器查询设备策略时的崩溃后，空间内能显示 Google 官方的「Add account」。选中并点「OK」，系统仍在添加账号时拒绝了与商店登录相同的权限。[真机前后对照](sandbox/blackbox-light/README.md)

使用只在原轻量空间注册的测试账号类型，确认旧壳会把分两步添加账号的请求送到个人区。更新后空间会直接返回不支持。原版商店现已能收到添加 Google 账号失败的回执，实测仍停在「Sign in」页。[会话去向和商店复测](sandbox/blackbox-light/README.md#分两步添加账号的请求去了哪里2026-11-13)

运行 `bash mobile/build.sh android-preview` 可生成可并存的实验客户端 `mobile/.build/android/Cage-android-experimental.apk`。正式客户端首页继续使用「连接电脑」。本机开发包沿用原来的测试签名，可覆盖安装到对应的实验版组件。当前独立 Google 安装包适用于 Android 16 arm64，源自 [MindTheGapps 的 Android 16 发布包](https://github.com/MindTheGapps/16.0.0-arm64/releases/tag/MindTheGapps-16.0.0-arm64-20261023_034858)，保留 Google 原签名。

2026-11-13 真机联测从实验版首页进入，核对了组件发现、代理地址校验、保存与清除、沙箱启动，以及返回首页进入电脑配对页。使用原有单节点配置做联网对照，手机上启动核心后从首页打开壳内的原版持续探针。首轮主、子进程请求均曾超时；加入助手接收及交付连接的日志后复测，主进程和系统 curl 按域名、数字 IPv4 发起的四条请求均命中代理出口，当时系统报告蜂窝、非 VPN。首次超时原因仍待确认。测试结束已停止核心并清除临时节点配置。

## Android 本机沙箱试验

### 当前进展与下一轮开发（2026-11-13）

本机开发主线是 **BlackBox 轻量壳 + 手机本地 Mihomo**。以下结论来自未 Root 的 Android 16 真机，测试期间手机使用蜂窝网络，没有启用 Android VPN。测试目标限于出口检测站和指定 IPv4 的新建 HTTPS 连接。

| 路径 | 已验证结果 |
| --- | --- |
| SIM、语言和时区 | 同一诊断 APK 在个人区看到双卡就绪、`zh-CN`、`Asia/Shanghai`，在来宾看到两槽无卡、`en-US`、`UTC`。覆盖所测电话接口、应用资源语言和 Java 默认时区。 |
| 原版测试 App 主进程 | 默认 HTTPS 域名请求和该探针的固定 IPv4 请求均取得手机代理的同期出口。只停本地核心后，两类新请求均失败。 |
| App 自己启动的系统 curl，按域名访问 | 保留原有 `-4` 参数，同一子进程在线时取得代理出口。停止核心后新请求失败；另一次保持核心运行，模拟上游不可达也失败，恢复上游后再次成功。子进程沿用系统 curl，联网由壳适配。 |
| 同一 curl，用 `--connect-to` 指定数字 IPv4 | 配套助手已在真机完成三段对照。同一子进程在线时读到代理出口，停止本地核心后失败，重启后再次读到代理出口。核心停机期间手机蜂窝仍可访问同一数字地址。 |

**主进程域名 HTTPS 的 `SecurityException` 已在测试范围内修复。** 真机异常栈显示 Android 的 HTTP 客户端进入系统 DNS 查询，而来宾没有直接联网权限。修复后，检测站的 Java HTTPS 连接显式经壳内代理交给平台 TLS 实现；原探针三次冷启及第四次在线域名请求均取得代理出口。第四次主进程数字 IPv4 出现一次 `IOException`，其原因尚未确认。下一轮优先复现这一失败，并检查代理恢复后的首次新请求。[调试记录与原始异常栈](sandbox/blackbox-light/README.md)

之后再扩展到其他目的地址、其他 App 和网络切换。UDP、公网 IPv6、已建立的长连接及官方 Claude App 兼容性仍待验证。新版在两个来宾同时驻留时采得 6 个进程合计 PSS 289.9 MiB，采样未计短命 curl；与旧原型的 265.2 MiB 运行条件不同。[独立网卡实验](#独立来宾网卡接入本地-mihomo2026-11-12)保留作备选，已验证命令行程序的 IPv4 出口和断线行为，尚未运行完整 Android APK。

「Cage 空间测试」是可以与 Cage 并排安装的独立测试 APK。第一版验证三项需求。

| 需求 | 手机上怎样验收 |
| --- | --- |
| 本机运行 | 不配对电脑即可打开测试应用。在个人资料创建 Android 工作资料后，从带公文包的图标打开工作区副本。 |
| 应用数据隔离 | 在个人区写入测试标记，首次打开工作区应显示「尚未写入」。在工作区写入另一标记，再回个人区确认原标记仍在。 |
| 系统状态读回 | 两侧分别查看卡槽状态、默认 SIM 归属地、注册网络国家、当前网络类型、语言和时区。允许两侧读数相同；不可用或权限受限单独显示。 |

工作资料共用手机的电话硬件。原型展示 Android 实际返回的值，不采集卡号、号码或设备标识。点「检测本区公网出口」后，应用向 icanhazip 的 IPv4 域名和 Cloudflare 的 IPv4、IPv6 地址分别发起新的 HTTPS 请求。检测服务可以看到请求的出口 IP；请求不携带 SIM、时区或账号信息。地址探测会忽略可选的 HTTP 代理设置，以验证普通应用能否自行联网。如果工作资料中已经安装官方 Claude，可从工作区测试页打开它。

Windows 构建需要 JDK 17+、Android SDK Platform 35 和 Build Tools 34 或更新版本。设置 `JAVA_HOME`、`ANDROID_HOME`，在仓库根目录执行 `./mobile/sandbox/build.ps1`。生成的 `mobile/.build/sandbox/Cage-Sandbox-debug.apk` 可直接在 Android 8.0+ 安装。安装后在个人区打开应用，按系统提示创建工作资料。Android 9 及以上可用页面上的系统切换按钮往返两个副本，也可从应用列表的工作区打开。系统禁止创建时页面会提示，已有的其他工作资料或厂商分身可保留。

Android 16 真机已验证两个副本各自保存标记，来回切换后均能读回原值。两侧报告相同的双卡就绪状态、默认 SIM 归属地、运营商、语言和时区。个人区报告「移动网络 + VPN」，工作区只报告「移动网络」。在未启用工作区 VPN、已移除 USB 转发的条件下，工作区通过域名成功取得公网 IPv4，与同期 Windows Cage 代理出口不同。两个 IP 字面地址请求超时，单项超时不能证明断网保护生效。测试使用 Cage 自己的普通应用进程。

整个工作区的目标包括官方 Claude 在内的原生应用都经过指定出口，上游断开后无法直连，Android 网络接口报告真实的非 VPN 连接，同时隔离 SIM 和时区。当前个人手机的工作资料不满足这些条件：它没有为单个工作区设置或屏蔽 SIM 国家、运营商及系统时区的标准接口；工作区 VPN 会被系统标记为 VPN。后续若采用独立 Android 系统，可在其上游网关验证代理和断网策略，并在来宾系统内单独验证电话与时间环境。

### BlackBox Reborn 真机验证（2026-11-12）

在型号 2410DPN6CC、Android 16（API 36）的未 Root 手机上安装了 [BlackBox Reborn v2.1.0 发布包](https://github.com/fdavids77/BlackBoxReborn/releases/tag/v2.1.0) 和 Cage 空间测试 0.3。新版诊断在首页显示默认和逐槽 SIM 状态、SIM 与注册网络的国家、运营商名称及 MCC/MNC、默认订阅与数据／语音／短信订阅 ID，以及活动订阅列表。订阅 ID 是本机索引。探针不申请电话权限，独立显示空列表、权限受限和服务不可用。语言、时区及网络可按按钮另行读取。

个人区对照读到两个就绪卡槽、SIM 运营商名称与数字码，以及有效的默认订阅 ID。与此同时，活动订阅列表返回 0 项。该列表不能单独用来判定无 SIM。

BlackBox 能打开主页。其「已安装应用」入口搜索 Cage 无结果；「手动选择」能选中同一 APK，日志也确认解析到了 Cage 包名，随后 `CopyExecutor.exec` 在构造 `File` 时发生 `NullPointerException`。容器最终报告 0 个应用，没有启动 Cage 诊断进程。**容器内 SIM 状态未知**；独立时区和语言、非 VPN 固定出口、断代理后的主／子进程直连均未测试。

**修补版真机结果：导入成功，SIM 隔离失败。** v2.1.0 的兼容解析代码设置了 `ApplicationInfo.sourceDir`，却没有填充复制阶段使用的 `Package.baseCodePath` 和启动所需的组件列表。[Android 16 导入补丁](../patches/blackbox-reborn/android16-apk-import.patch) 在 API 36 上复用系统的完整 APK 解析器，并要求验证证书。测试壳以单独包名安装，保留发布版的原生库。手动导入后，容器记录了 Cage 包的安装成功事件，重开容器仍能从图标启动该包。

个人区已安装的 APK、导入文件和本机 Cage 0.3 产物逐字节摘要一致。容器里的诊断进程运行在测试壳的 Android UID 下，与个人区的 Cage 进程 UID 不同。Cage 生成 SIM 读数后查询工作资料切换入口时，系统因调用包名与 UID 不匹配拒绝访问，页面未完成显示。为读取已经生成的文本，在测试壳中只对 Cage 诊断界面的这次异常做观察，再抛回原异常。观察版逐行与个人区读数比对，只记录相等标记，结果为 `hostMatches=1111111111111`。双卡就绪、SIM 归属国、运营商名称与 MCC/MNC、默认订阅索引均与宿主相同；两侧活动订阅列表均为 0 项。按 SIM 停止条件结束，未进行独立时区／语言、非 VPN 固定出口及断代理后的主／子进程直连验证。

### BlackBox 来宾电话服务隔离复测（2026-11-12）

在上述 Android 16 导入补丁之上应用[来宾电话服务补丁](../patches/blackbox-reborn/guest-telephony-services.patch)。仅在来宾应用进程中拒绝对电话、订阅、用户电话信息和电话事件服务的请求，个人区和容器管理进程继续使用原配置。手机保留真实 SIM。复测使用同一个 Cage 0.3 APK，个人区的 13 行读数与前次基准一致。沿用上述页面观察方式，逐槽单列返回状态，不读取手机号、IMSI 或卡序列号。

| 检查项 | 个人区 | 壳内 Cage 0.3 |
| --- | --- | --- |
| 默认 SIM 和逐槽状态 | 默认就绪，槽 1、2 均就绪 | 默认及两个槽的状态查询均返回权限受限；仍能枚举两个活动逻辑槽 |
| SIM 归属国、运营商名称、MCC/MNC | 三项均有值 | 归属国与名称返回空值，数字码查询权限受限 |
| 默认、数据、语音、短信订阅 | 四项均返回有效订阅 ID | 默认、数据和短信均无有效订阅，语音查询权限受限 |
| 活动订阅列表 | 0 项 | 查询权限受限 |
| 注册网络国家、运营商名称、MCC/MNC | 三项均有值 | 国家查询权限受限，名称与数字码返回空值 |

这里的槽数量来自 `getActiveModemCount()`。它暴露了设备的双逻辑调制解调器配置，单凭此数不能推断插着两张卡。按卡槽也在验收范围内的口径，本轮停在 SIM 阶段。结果只覆盖 Cage 0.3 在该机型上的这些 Android 接口，未证明任意原生应用的所有读取路径都已隔离。

### Android 16 无卡返回值复测（2026-11-12）

保留首轮来宾电话服务补丁，再叠加[无卡返回值补丁](../patches/blackbox-reborn/android16-no-sim-replies.patch)。运行于 API 36 时，本地虚拟电话／订阅服务按设备接口的事务名称回答已知查询。未识别的请求继续拒绝。补丁沿用原有服务边界和观察方式，未修改 Cage 0.3 APK。个人区复测仍为双卡就绪，13 行对照数据与首轮相同。

| 同一 Cage 0.3 读取项 | 首轮测试壳 | 无卡返回值测试壳 |
| --- | --- | --- |
| 默认 SIM、槽 1、槽 2 | 三项均权限受限 | 三项均为 Android 定义的「无卡」，仍可枚举两个逻辑槽 |
| SIM 归属国、运营商名称、MCC/MNC | 前两项为空，数字码权限受限 | 三项均显示「系统未返回」 |

```sh
go build -o ./cage-mobile-link ./cmd/cage-mobile-link
```

1. 在电脑上用 `cage-mobile-link init --state <新私有目录>` 创建主机身份，记录显示的公开指纹。以后可用 `fingerprint --state <原目录>` 再次查看。
2. 手机打开 Cage，在“这台手机的指纹”下复制公开指纹。对照手机屏幕，在电脑上执行 `cage-mobile-link trust --state <原目录> --peer-pin <已核对的手机指纹>`。
3. 在电脑上生成这台手机的连接文件，并保持连接助手运行。官方中继允许直接创建连接。请填写主机身份目录、新连接文件路径，以及 Cage 后台程序和配置文件的绝对路径。

```sh
./cage-mobile-link host --state "$host_state" --connection-out "$new_connection_json" \
  --cage-bin "$cage_binary" --config "$cage_config"
```

4. 通过自己的私有文件传输方式将 JSON 送到手机。在 App 中点“导入连接文件”，对照**电脑独立显示的公开指纹**，确认与手机上填入的指纹一致。勾选核对项，点“保存已核对的主机”，然后点“重新连接”。换用另一台电脑或更换电脑密钥时需再次核对。

进入工作台后，在左侧栏的「Claude Code」下选择项目，新建或继续会话。工具需要授权时，手机显示本次调用的具体参数，可选择“允许一次”或“拒绝”。此入口列出通过 Cage 会话界面创建的对话，普通终端里手工启动的 CLI 仍在原终端操作。

续聊前，Cage 检查原会话使用的账号和模型服务地址，避免把历史发到另一个服务。主机无法确认所用配置的身份时，手机会提示本次仅支持一轮；可以新建会话再发消息。

## 使用自己的 VPS

部署[自建中继](../deploy/relay/README.md)后，在桌面「设置 → 远程连接」选择「自建中继」，填写 VPS 的 HTTPS 地址并保存。手机进入设置并展开「中继设置」，开启自建中继，填写同一地址并保存。需要管理令牌的自建中继只在电脑端填写令牌。选择官方中继并保存可恢复默认。新配对采用保存的地址，手机导入连接文件时会自动填入同一地址。自建中继要求管理令牌时，在上面的 host 命令中同时指定 `--relay` 和 `--admin-token-file`，明确私有令牌的接收方。

已配对的手机继续使用原来的地址与凭据。要迁往另一台中继，扫码设备在桌面设置中移除后重新扫码；命令行配对设备用下文的 revoke 撤销后重新登记。

## 下次使用

点左上角的 Cage Logo 打开侧栏，点侧栏底部「退出」回到首页。需要切换电脑时，点首页的「连接电脑」，在卡片的「已连接设备」中选另一台电脑。长按设备可取消这次连接，配对记录会保留。

Claude Code 的项目可以各自展开，方便在不同项目的会话之间切换。会话进度自动刷新；读取失败时可以点提示中的「重新读取」。聊天通过气泡区分消息来源，输入框为大圆角，右侧箭头用于发送，运行时显示停止按钮。

在已配对的手机上，短暂断网时可以留在当前会话。网络恢复后，工作台再次读取进度时会重新验证电脑身份并恢复连接，输入框里的草稿仍在。若发消息或审批时断线，先看电脑返回的最新记录。已收到的消息会显示在历史里；电脑仍在等待同一项审批时，手机会重新显示可选的「允许一次」和「拒绝」。

主动断开或重新打开 App 后，从「连接电脑」卡片选择已配对的电脑，再打开原会话即可继续。如果使用命令行连接助手，电脑重启后先启动 Cage，再运行以下命令恢复该助手的配对：

```sh
./cage-mobile-link host --state "$host_state" --serve-saved
```

连接文件包含中继地址、电脑公开指纹和持久查询凭据，请只交给配对手机。Android 用独立的 Android Keystore AES-GCM 密钥加密查询凭据，并将密文绑定到已核对的中继地址和指纹。iPhone 将记录保存在仅限本设备、解锁时可访问的 Keychain 项中。设备签名私钥由 Android Keystore 或 iPhone Secure Enclave 保管。仅 iPhone 模拟器的 Debug 构建使用单独的软件测试密钥，设置中的设备指纹旁会注明。网页只访问本机受限的会话接口。

在手机点“忘记主机”会清除保存的主机地址、指纹和重连凭据，手机仍使用自己的设备签名身份。要同时在电脑端撤销访问，执行 `cage-mobile-link revoke --state <主机身份目录>`。使用旧版单次邀请时，在电脑以 `--invitation-out <新邀请文件>` 代替 `--connection-out`，手机手工核对并保存中继地址与电脑指纹，再通过同一个导入入口打开邀请。单次邀请断开后需要新邀请。
