# 来宾隐私模块

此模块由上一级构建脚本的 `--privacy` 参数启用；`--privacy-modules` 可选择 `sim`、`timezone`、`vpn`。默认时区为 `Asia/Tokyo`，不修改 UTC 时钟。

后续 Android16 真机结果见 [真机报告](../../../PHONE-GBOX-VALIDATION-2026-11-15.md)：SIM/VPN 已测路径通过，WebView 首脚本仍存在原时区泄露。扩展覆盖与验收按 [隐私风险与补充验收](../PRIVACY-REVIEW-2026-11-15.md) 跟踪；下文各 Privacy 版本的 MuMu 历史结论不代表真机全部通过。

2026-11-15 后续增量已随新 UI 合并安装：识别到 VPN 隧道时，`LinkPropertiesPrivacy` 返回空展示副本，清理隧道地址、DNS、路由、代理等元数据；不改真实链路或非隧道字段。Android16 活动隧道同步查询和默认回调对照通过；底层蜂窝链路仍有地址与 DNS/路由计数，不能称为全部网络身份隔离。14 项独立 Android 合成对象检查通过，最终实际接入、登录及数据保留证据见上述补充验收文末。网页首脚本与断线保护仍未通过完整验收，手机全局网络设置未改变。

策略仅作用于 `com.anthropic.claude` 和验收探针 `io.github.leexeo.cage.gboxprobe`。绑定到其他应用时停用策略并恢复记录的进程环境；GBox 管理进程及 Google 预置 APK 不改写。

Privacy12 已在 MuMu 单次冷启动取得完整 Probe06 报告，所测 SIM 属性、时区和 VPN 可见状态通过。三个原生属性入口 get/read/read_callback 和 getifaddrs 均有成功安装状态与实际命中，稍后加载的来宾 ARM 库经过同步刷新被纳入。Java/ICU、原生本地时间与属性、默认子进程、WebView 首个脚本及后续读数均为 Tokyo / +540，所测 UTC 对照保持一致。未选中的 SDK 属性和两个原本缺失的容量属性保留原结果；硬件容量数不作为 SIM 存在或隐藏的判据。Java SIM 在外层和来宾都为空，无阳性对照，不能独立归功于屏蔽；运营商信息在原生和子进程路径有阳性对照。

上述结论仅覆盖自有探针已记录的读取路径。该次探针运行的新进程保留既有来宾标记，未见相关崩溃，没有清数据、重新导入、账号操作或公网探针请求。随后真实 Claude 未登录启动通过，但未观察到其目标原生读取；Google 正确密码和条款步骤已完成，返回后账号列表仍空，Google 与 Claude 登录尚未验收。用户已停止设备工作，换电脑接续见 [接续说明](../../../HANDOFF-2026-11-15.md)。原生构造函数、JNI_OnLoad、纯 native 加载、返回前并发使用、直接函数地址读取以及 raw syscall/netlink 等边界仍在。

首版接入点：

- VLite 来宾 Context / Application 初始化：设置 Java、ICU、TZ 环境和现有 Native 属性映射。
- VLite Binder 调度：限制电话和订阅读取，处理网络查询返回值与 Messenger 回调；保留原有请求选择和调用链。
- 来宾 `Libcore.os`：过滤 Java 网络接口枚举中已识别的 VPN 接口。

Privacy08 修复了首次策略初始化过早的问题，默认子进程属性屏蔽随之生效。Privacy09 又修正内存映射解析计数，实际通过 nb ARM 和宿主 libc 的分配器归属校验。两版冷启动均取得完整报告，无相关崩溃且测试标记保留。Java VPN 状态和接口名、Java/ICU/原生 localtime、子进程 date 与属性过滤已生效；真实 WebView 首个脚本和加载后读数均为目标时区。父进程的三个原生属性入口仍暴露运营商和原时区，原生 getifaddrs 仍有 VPN 接口。第 09 版延迟快照确认后来出现了匹配当前来宾目录的 ARM 库，但原生拦截的筛选计数没有更新，实际命中仍为零。截至第 09 版整体屏蔽未通过；第 12 版的结果不能反推为这些旧产物已通过。

第 11/12 版使用 `Runtime.nativeLoad` 成功返回前的同步刷新，针对已测到的加载后读取缺口。ELF 构造函数、`JNI_OnLoad`、绕过 Java 的原生加载及返回前并发调用不因此成为已覆盖路径。Claude 原始库的定向静态检查未发现明确的早期目标 SIM／时区读取，但仍有未解析的间接调用；这不是全面覆盖证明，也不能代替实际 Claude 进程和登录验证。

Privacy10 的复制方法方案已确认失败：ART 在 `JNI_OnLoad` 中依赖原始 `Runtime.nativeLoad` 方法身份选择类加载器，复制方法虽然保留参数，却破坏了这一条件，导致 WebView 初始化时找不到 `DrawFunctor` 并退出。该版没有完整屏蔽报告。独立 Host Load Probe01 改用真正的 x86 JNI 包装并保持原方法身份，ARM 库初始化及嵌套加载通过，但 ARM 回调计数断言失败且实际数组没有保存。Probe02 补全诊断后，同一个宿主包装库已通过四个独立 ARM 库初始化、三次回调、嵌套加载、原错误对照和真实 WebView 本地页面；最终五次回调均查类和调用成功，没有异常。第 01 版失败未复现，根因仍未确定，不能把增加诊断说成已定位的修复。

Privacy11 的宿主桥在真实 GBox 中安装成功，两次 ARM 刷新完成；但更早的 Binder 线程空辅助入口崩溃阻止了完整报告，故该版没有屏蔽通过结论。独立 helper DEX 和 x86_64 库只作为 assets 打包，通过已确认的宿主 Context 提取到私有缓存，再交给 bootstrap 父加载器、空原生搜索路径的独立 DexClassLoader；APK 原生 ABI 不变。原方法身份保留，x86 包装直接转调原 x86 JNI 入口，成功后经显式 JNI 回调 ARM 策略库，不增加 Java 转调包装。helper 和回调类以全局引用保持；注册已开始或状态无法确认时不能当作未安装继续，观察器新增异常会向上传播。第 10 版复制方法观察器已移除，兼容库恢复为第 09 版原字节，原 17 项适配和 11 项必需检查保持。

Privacy12 只替换第 11 版兼容库，在 UID 回调可调用前发布两个已验证的辅助原入口，并进行映像/可写槽/当前值保护、读回与最终槽核验。实际日志确认两槽提前就绪、原 getter 序列保留及最终匹配，随后三次 host→ARM 刷新完成且无拒绝，四项读取钩子实际命中，完整报告通过所测屏蔽项。这次结果支持该修复有效，但不把一次无崩溃推定为所有并发问题已经排除。parent、host、child、WebView、全部 DEX、原 core 与预置 APK 都保持第 11 版原字节。依据为 `mumu/privacy12-result.json`、`privacy12-comparison.json` 及相关固定阶段日志；延迟八秒日志已取得，已知无权限的私有文件及进程内存未读取。

独立子进程探针已证明 x86_64 默认继承链的属性过滤和恢复可用，Privacy08 也已验证实际 GBox 中默认子进程的属性过滤；主动替换、清空或使用较早缓存环境的子进程不在该结论内。直接解析共享属性区、raw syscall/netlink 等路径未被覆盖。`TZ` 设置不等于 `getprop` 属性被屏蔽。实际流量出口和断线保护由独立网关承担：真实来宾的两项 IPv4 HTTPS 出口匹配，网关停止后的三项新 HTTPS 请求均未获得公网 HTTP 响应；该结果不等于所有协议零流量，在线 IPv6 TLS 也未完成。网络显示过滤本身不提供路由保证。完整性凭证和应用许可保持原有组件行为。
