## 原分析需要修正的结论

1. **子进程并非完全未覆盖。** [ChildPolicy.java](privacy/java/io/github/leexeo/cage/privacy/ChildPolicy.java) 和 [property_preload.c](privacy/child/property_preload.c) 已处理选中来宾的默认环境继承，覆盖指定 SIM 属性与时区。它们没有处理 `ro.debuggable`、`ro.secure`、`mount` 输出或子进程网络接口；显式清空、替换、提前缓存环境也不属于已通过范围。应补测具体路径，不能把所有 `ProcessBuilder` 读取统称为绕过。
2. **未在新增隐私模块看到标识处理，不等于底层容器完全没有隔离。** `ANDROID_ID`、安装来源和应用私有标识需要实测外层/空间之间的关系。按用户报告，Claude 的 `device_id_prefs.xml` 是应用生成并持久化的 UUID，不是 `ANDROID_ID` 派生值；两者分开验收，不能靠清数据或轮换 ID“修复”。
3. **未发现内联 `svc #0` 不能证明所有原生读取均可拦截。** 用户报告同时列出 libc `syscall`，此外还有直接函数地址、间接调用、系统库、后加载库和其他进程边界。字符串或导入符号存在也不能单独证明相应采集实际执行。
4. **Claude APK 中未找到旧 DroidGuard/SafetyNet 调用，不代表 Google 服务内部没有调用。** 真机报告记录了独立 GMS 的 DroidGuard 服务连接和返回；Claude 包内的静态零命中不能排除包外路径。权限声明也不能当作实际读取证据。
5. **硬件证明、Play 判定和 TLS 信任属于独立验收。** 改系统属性不证明这些链路通过；登录成功也不能推出所有完整性等级通过。保留原组件、真实判定、异常和签名，不伪造凭证、许可、信任结果或成功状态。

P0 表示在声称相应隐私能力完整可用之前必须解决；P1 表示扩大覆盖结论之前必须完成定向验证。优先级不是新一轮设备操作授权；沿用对应任务的设备范围和停止条件。

### R01 P0 WebView 首脚本及渲染进程重建

**状态：已复现未通过。** [WebView 说明](privacy/WEBVIEW-ANDROID16.md) 和真机报告都保留首脚本竞态。Java 回调返回或后续页面显示 Tokyo，不能替代首脚本结果。

后续进展：[独立确认后加载实验](privacy/renderer-lab/README.md) 在 20 个不同应用进程、35 个自有目标页面上通过首脚本、iframe、worker 及已测重建路径，故意不满足确认条件时不加载页面。该机制尚未接入 Cage：公开确认入口在 JS 关闭时无有效结果，提前调用会影响 profile 选择，同步历史恢复不能直接改为异步。因此 R01 仍未完成，不能更改现有生产 UI 的风险判定；原 UI、Cage 安装包和数据未变。

随后验证的 [隔离 renderer 原生初始化路线](privacy/renderer-lab/service-experiment/README.md) 不改页面加载 API，也不依赖上述预热。10 个独立应用进程、15 个目标页面及 5 次 renderer 重建均为 Tokyo；浏览器侧与 renderer 侧必须同时初始化。生产接入被自动审批拒绝，尚未获准将该高影响服务装配接入实际 Cage。GitHub 中仅保存独立实验，不将其标为已修复或自动启用。

本轮核对的 renderer 时区更新仍是无完成回执的异步通知，未取得可验证的初始化入口。仅增加明确的“不保证首脚本”诊断，未加固定延时或修改页面读数。最终包冷启动对照仍为 `FAIL_INCONSISTENT_TIMEZONE`；新 UI 继续显示网页时区未通过。

补充验收：

- 在 renderer 初始化阶段确认目标时区生效，再允许目标页面脚本运行；固定延时、偶然预热成功不能作为完成条件。
- 覆盖首次创建、renderer 回收重建、多个 WebView/profile、页面刷新、后台恢复，以及实际使用到的 iframe/worker。
- 重复冷启动，分别记录首脚本与后续 `Date`/`Intl`、偏移和 UTC 对照；不修改页面或探针读数来通过检查。

### R02 P0 实际出口与网络故障时禁止直连

**状态：真机未验收；MuMu 仅有历史有限请求证据。** 隐藏 VPN 标记与路由保护分别判定，不能从网络错误或没有 HTTP 响应推断零外泄。

用户明确选择“先只完善 Cage 和检测，不改手机全局网络设置”。本轮新增 [只读前置检查和离线验收工具](network-acceptance/README.md)，未停止 FlClash、修改节点或系统设置。最终包哈希匹配，但手机 `always_on_vpn_app=null`、`lockdown=0`，前置结果为 `BLOCKED_PRECONDITION`，网络故障试验 `NOT_RUN`。普通 Cage 进程不能完整读取系统设置时，UI 保持“未能确认”；即使配置已开启，也不能由静态配置得出断线验证通过。

### R03 P1 网络地址与元数据可见性

**状态：VPN 隧道元数据过滤已实现且通过有限真机对照，完整网络身份隔离未完成。** [GuestPrivacy.java](privacy/java/io/github/leexeo/cage/privacy/GuestPrivacy.java) 对已识别隧道调用 [LinkPropertiesPrivacy.java](privacy/java/io/github/leexeo/cage/privacy/LinkPropertiesPrivacy.java)，返回新的空展示对象，去掉地址、DNS、路由、域信息、代理、MTU、私有 DNS、DHCP/NAT64 及堆叠信息；不改变原对象、真实网络句柄或路由，非隧道对象保持原字段。

[探针](probe/ProbeActivity.java) 已增加同步链路、回调和 Java 接口地址的类别/数量；不保存原始 IP、MAC、域名、DNS 地址或代理端点。最终外层存在活动 VPN 和非空元数据，来宾活动链路及默认回调的所测字段为空，判定为 `PASS_FOR_RECORDED_ACTIVE_TUNNEL`。UI 详情明确限定这个范围。

**新增实测边界：** 来宾 `allNetworks` 中的非隧道蜂窝网络仍有 IPv4/IPv6 地址、DNS 和路由计数，未被本次隧道过滤处理。原始地址相同/不同、socket 本地端点、Wi-Fi、原生地址与 raw netlink 尚未验收，不能将当前通过写成“完整网络身份隔离”或“零外泄”。跨进程 Network 身份亦未独立关联。

补充验收：

- 覆盖 `NetworkInterface` 地址枚举、`LinkProperties` 地址/DNS/路由/域信息/代理/堆叠链路，以及适用的 Wi-Fi 元数据；明确哪些属于当前允许暴露的能力，哪些必须隔离。
- 对比同步查询、网络回调、原生 `getifaddrs` 和实际 socket 的本地端点；单独测试子进程接口读取与 raw netlink/syscall。
- 原始地址留在内存，只落盘“与外层相同/不同”、地址类别、计数和固定结果；不得为了诊断新增持久 IP、MAC 或网关凭据日志。
